# Wave A: feedback questions

Three questions go in the invitation. The rest are for a follow-up DM or a short call, and only after the
tester has answered the first three. Never send the whole list at once.

## In the invitation (always)

1. Which OS, and desktop app or CLI? (Also the Claude Code version, if they know it: `claude --version`.)
2. What was the first thing that confused you or did not work?
3. If you could keep only one feature, which one?

## Install and first run

4. Did the welcome wizard open on the first new session? Which profile did you pick (Minimal, Productive,
   Playful) and why?
5. How long from the first command to "it works"? Did you have to read the README to get there?
6. Did anything in the first session look wrong in your terminal: the status band wrapping, colours,
   Hebrew or other RTL text, a pane that did not fit?

## Daily use

7. Did the status band tell you something you acted on (context high, cost, a repeated failure)? What?
8. Did a guard block anything? Was the block right, and was the receipt clear about why?
9. Did the advisor or any toast interrupt you when you did not want it? How often?
10. Did you switch anything off? What, and what made you do it?
11. Did the companion make you smile, or did you turn it off? (Both answers are useful.)

## Trust

12. Did you read the "What leaves your machine" section? Did anything there surprise you?
13. The correction-capture and session-finder features send text to Haiku through your own account by
    default. Would you have wanted that off by default, or is "disclosed and switchable" enough?
14. Would you install this on a work machine? If not, what would need to change?

## Closing

15. What would make you tell a colleague about it? What would stop you?
16. May I quote one sentence of yours, with first name or anonymously, in the launch posts? (Record the
    answer in the CSV column `quote_ok`.)

## How to read the answers

- Three testers naming the same first problem: fix it before any post, whatever it is.
- A feature named as "keep one" by two or more testers: lead the launch copy with it.
- Any "I would not install this at work" answer: the reason goes into the README's limits section, not
  into a rebuttal.
